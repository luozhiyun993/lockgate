# 桌面代理守护应用需求

## 已确认

- macOS 主窗口与菜单栏状态图标；关闭主窗口后继续监控。
- 支持 Claude Desktop 和 Claude Code，可分别启用保护，仅处理当前用户明确识别的目标进程。
- 实现代理检测、启动门禁、持续监控、异常锁定、手动恢复。
- 第一版采用进程级急停，接受检测及终止之间存在时间窗口，不承诺网络层零直连。
- 不依赖特定代理软件：自动识别系统隧道与 macOS 静态 HTTPS 代理。
- 出口规则参考 claude-switcher：默认使用 Cloudflare trace 返回的地区与目标地区比较，普通 IP 变化只提醒。
- 增加可选的手动指定出口 IP 设置；填写并启用后，在地区检查之外增加地址严格匹配，不匹配时急停并锁定。未启用时不强制固定 IP。
- 自动检测负责展示当前出口，不自动更改用户指定的 IP 或目标地区。
- 提供可供用户验证功能的测试方式。
- 运行中网络不通或出口检测超时不触发急停，显示状态未知或网络告警并持续检测；不能将检测失败标为检查通过。
- 成功观测到不符合出口要求的地址才触发出口异常急停。用户重点关注预期日本出口变成其他国家或地区出口的情况。

## 初版环境发现（历史背景，不作为运行依赖）

- 本机安装 Clash Party 2.0.4；配置目录为 mihomo-party。
- 保存的配置启用了 TUN，未启用系统代理，外部控制器地址未设置。
- 这些是静态配置事实，不代表实时代理、路由或端口健康。

## 后续确认

本轮关键行为已获用户确认：

- 确认系统 HTTPS 代理端口拒绝连接，或无系统代理且完整探测路由包含非隧道路径时急停并锁定。缺失路由、端口超时及未知配置不等于确认异常。
- 启动和手动恢复必须取得有效出口并通过检查；网络未知时不放行。
- 提供不影响真实进程的模拟测试，以及用户明确触发的真实急停测试。

## 第一版实现约定

- 运行中持续校验地区和指定 IP，超出参考项目保镖仅检查代理进程与 TUN 的实现。
- 锁定且保护启用时，匹配到的外部启动也会在巡检后急停；不承诺阻止其第一个请求。
- 首次打开及重开默认观察模式，由用户显式启用进程保护；已有锁定持久化。
- 不安装 root 服务、不自动修改代理、不自动启动 Claude。

## 内置代理（0.4.0，取代上面的部分约定）

- 新增内置 mihomo 代理：订阅管理、节点选择、系统代理、TUN 模式、内核内嵌并可升级。
- 因此「不自动修改代理」「不读取订阅」只适用于门禁检测本身：检测仍然只看系统代理与路由，不依赖内置代理的状态；内置代理按用户操作修改系统代理。
- TUN 采用一次性授权的 setuid 内核，不安装常驻 root 服务。
- 门禁现在认可只覆盖本机和固定私有网段的系统代理绕过条目（此前任何 IP / 网段条目都判为不可确认）；公网地址、其他网段和 Fake-IP 网段仍判为不可确认。

## 内核阻断（0.4.0）

- 网络阻断新增「通过内置代理阻断」：由 mihomo 的规则拒绝访问列表内地址的连接，与原有的系统扩展方式并存、可分别开启。
- 语义与系统扩展方式一致的部分：保护启用后默认拒绝，检查通过并解锁才放行；锁定时断开已有连接；受管启动要求阻断方确认放行。
- 不一致的部分：按地址而不是按进程，对所有经过内置代理的应用生效；没有失联租约，Lockgate 或内核退出后不再拦截。

## 已实现与覆盖边界

- 使用所选隧道或显式 HTTPS 代理的 Cloudflare trace；规范化 IPv4/IPv6 地址用于比较，但不完整验证双栈旁路或目标分流。出口探针通过不等于所有 Claude 流量均走同一路径。
- 不读取代理软件进程、配置文件、订阅或控制器。PAC、仅 SOCKS、仅 HTTP、冲突的按网卡配置与无法确认的绕过规则保持未知，启动门禁关闭。
- 受管 CLI 清理旧代理和绕过环境变量，再应用当前系统代理；外部启动的 CLI 不保证遵循系统代理。
- 保护期间切换系统代理端点或代理/隧道模式会锁定，避免已有进程保留旧环境；仅隧道编号变化会废弃旧出口结果并重新检测。
- 本机巡检约 2 秒、网络检测约 10 秒，网络请求有超时，两个监控循环独立。
- 急停限定当前用户与明确路径，复核进程启动身份；先 TERM，再对仍存在的匹配进程 KILL。
- 锁定持久化，启动和手动恢复都重新检查；CLI 在终端实际执行前再检查心跳及门禁。
- 使用说明和测试步骤见 README.md 与 docs/testing.md。
